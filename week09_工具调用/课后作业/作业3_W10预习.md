# 作业 3：W10 预习 —— Function Calling / MCP / 普通 API 调用

## 一、三者各一句话

| 名词 | 一句话 |
|---|---|
| **Function Calling** | 模型侧的机制：模型自己不会执行任何东西，只输出「我要调哪个函数、参数是什么」，执行权在我们程序手里——W9 手写的那 60 行循环就是这个机制的最小实现。 |
| **MCP（模型上下文协议）** | 工具侧的协议：规定「工具长什么样、怎么被发现、怎么被调用」，让不在本机的工具也能用统一接口挂到任何支持 MCP 的模型上。 |
| **普通 API 调用** | 程序侧的请求：我们写代码发 HTTP 请求、拿 JSON 响应，什么都不由模型决定——调用哪个接口、传什么参数，都是程序员在代码里写死的。 |

一句话串起来：**普通 API 是「人写死的调用」，Function Calling 是「模型决定调什么」，MCP 是「把工具标准化，让别人的工具也能被模型发现和使用」。**

## 二、希望 MCP 帮我接上的 2 个外部工具

### 工具一：学校教务/成绩系统查询

- 用途：问「这次 HSK4 模拟考我们班平均分多少」「张三的期中成绩是多少」时，直接查教务系统，而不是让我手动导表格。
- 为什么需要 MCP：数据在学校系统里，不在我的电脑上，我只想接一个标准接口，不想为每个系统写一套爬虫。
- 大致的输入/输出：输入「班级 + 考试名称」，输出「平均分、最高分、最低分、各分数段人数」。

### 工具二：在线词典（汉典 / 现代汉语词典 API）

- 用途：学生问「『踌躇』和『犹豫』有什么区别」时，查权威词典的释义和例句，而不是让模型凭记忆编。
- 为什么需要 MCP：词典是第三方的、会更新，我只要按标准接口问它，不用自己维护词库。
- 大致的输入/输出：输入一个词，输出「拼音、释义、词性、例句、近义词辨析」。

## 三、预习笔记：我理解的三层关系

- **W9（本周）**：工具是我自己写的函数，放在 `TOOLS` 字典里，接口是「函数名 + 参数列表」。接线方式是我定的。
- **W10（下周）**：工具由别人提供，接口要统一成协议（MCP），模型通过协议发现「有哪些工具可用、每个工具要什么参数」。
- **一句话区别**：这周解决「模型怎么决定用工具」，下周解决「工具从哪来、怎么接进来」。
