# 作业 2：给 tool_agent 加第 4 个工具「课文难度评估」

## 一、工具定义

| 项 | 内容 |
|---|---|
| 工具名 | `text_level` |
| 输入 | ① 课文：`data/` 下的文件名（如 `"愚公移山.txt"`），或直接一段课文原文<br>② 目标等级：如 `"4"` 或 `"HSK4"` |
| 输出 | 一段话：全文字数、词表覆盖率、目标等级以上的超纲词清单、词表外片段中最长的几个 |

对应的调用长这样：

```json
{"tool": "text_level", "args": ["愚公移山.txt", "4"]}
```

## 二、为什么选这个工具

W8 的预习调查里，「课文难度与覆盖率评估」是 3 位同学写过的愿望（徐培原、汪佳琪），讲义也把它列为作业 2 的推荐第 4 工具。它和已有三个工具的区别很明显：

| 工具 | 处理什么 | 靠什么 |
|---|---|---|
| `get_time` | 系统时间 | 读时钟 |
| `calc` | 数值计算 | 白名单 AST |
| `hsk_level` | 单个词的等级 | 查 CSV |
| **`text_level`** | **一整篇课文** | **切词 + 统计** |

前三个都是「取一个值」，第四个要对一段文本做结构化统计——这才能看出「加工具不用改主循环」。

## 三、实现要点

1. **不引入分词库**。中文没有空格，装 jieba 当然更准，但会多一个依赖。这里用「词表最长匹配」：从当前位置往后按最长优先在词表里找，找到就切一个词出来；找不到的连续汉字连成一个「词表外片段」。
2. **覆盖率按字数算，不按词块数算**。词块长度差异很大（「愚公移山」4 字 vs 一个未收录长句 20 字），按词块数会把覆盖率算虚高。
3. **超纲词只统计词表里有的**。词表里等级 > 目标等级的才算超纲；词表外的片段单独列出来当「待人工判断的生词」。

代码在 `week09_工具调用/课后作业/tool_agent_4tools.py`，只比课堂版多了 `text_level` 一个函数，外加 `TOOLS` 和 `SYS` 各改一行——**`parse_calls()` 和 `run()` 一行没动**。

## 四、真实运行结果

### 4.1 直接调用工具

```python
text_level("愚公移山.txt", "4")
```

```

HSK4 以上超纲词 7 个：寒暑易节（6级）、叩石垦壤（6级）、智叟（6级）、愚公（6级）、
愚公移山（5级）、无穷无尽（5级）、子子孙孙（5级）；
词表外片段 174 处，最长的如：本文件古文部分可作为文化…、课堂教学建议使用教材改编…、
命令夸娥氏的两个儿子背走…、河南党史方志网等公开文本…、我和你们尽全力铲平险峻的…
```

换成目标等级 6：

```

```

同一篇课文，目标等级一换，超纲词就变了——这正是「难度评估」该有的行为，工具确实在按目标等级判断。

### 4.2 模型自主调用

问：**「我在给 HSK4 的学生备《愚公移山》，帮我看看这篇课文难度如何，有哪些超纲词？」**

模型自己决定调 `text_level`，并在拿到结果后给出一段像样的分析，其中有一条是我没预料到的：

> 文中还混入了教材说明、网站来源等非课文文字（如“课堂教学建议使用教材改编”“河南党史方志网等公开文本”），这些片段拉低了覆盖率的统计，备课时应先剔除，再做正式难度判断。

它读懂了「词表外片段」这一列里混着文件头部的说明文字，主动指出这是**数据问题而不是课文难度问题**。这条不是我在提示词里教的，是它自己从返回结果里看出来的。

## 五、已知限制（要老实写）

1. **样本词表只有 13 个词**（`data/生词表.csv` 是课程样例，恰好围绕《愚公移山》收录了「愚公」「智叟」「叩石垦壤」等）。所以覆盖率 8.1% 这个数字**不代表课文真实难度，只代表词表很小**。换成完整的 HSK 分级词表，这个数才有意义。
2. **`data/愚公移山.txt` 不只是课文**：文件里有出处说明、古文原文、白话译文、教学建议。做难度统计前应该只取课文正文，否则说明文字会混进「词表外片段」。
3. **最长匹配不是真分词**：遇到「把字句」这类词表里没有的复合词，会被切成更小的片段。够用于「哪些词可能超纲」的判断，但不够做精确的词频统计。
