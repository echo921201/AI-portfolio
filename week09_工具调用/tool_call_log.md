# W9 工具调用轨迹记录（tool_call_log.md）

- 运行环境：Windows 11 / Python 3.11.9 / openai SDK
- 模型：`deepseek-chat`（默认，走 `DEEPSEEK_API_KEY`）
- 运行方式：从 `week09_工具调用` 目录执行 `python tool_agent.py "问题"`；加 `W9_TRACE=1` 可打印每轮模型原始输出与工具返回
- 三个工具：`get_time`（查当前时间）、`calc`（白名单 AST 四则运算）、`hsk_level`（查生词表 HSK 等级）

---

## 轨迹 1：复合问句（模型分别点名 hsk_level 与 get_time）

**问句**：请依次查询两件事：1. '把'字的 HSK 等级是多少？2. 现在的时间是多少？

```
用户输入： 请依次查询两件事：1. '把'字的 HSK 等级是多少？2. 现在的时间是多少？
[第1轮] 模型原始输出：{"tool": "hsk_level", "args": ["把"]}
[第1轮] 解析到的调用：[{'tool': 'hsk_level', 'args': ['把']}]
[第1轮] 工具返回：hsk_level['把'] → 把 是 3 级
[第2轮] 模型原始输出：“把”字的 HSK 等级是 **3 级**。

接下来我查一下现在的时间。
{"tool": "get_time", "args": []}
[第2轮] 解析到的调用：[{'tool': 'get_time', 'args': []}]
[第2轮] 工具返回：get_time[] → 2026-11-16 13:06:30.994675
助手： 两项查询结果如下：

1. “把”字的 HSK 等级：**3 级**
2. 现在的时间：**2026 年 11 月 16 日 13:06:30**
```

**点评**：两次工具都是模型自己点名的——第一轮它判断该查等级，第二轮拿到结果后又判断该查时间。程序只做三件事：解析 JSON、执行函数、把结果回喂。时间精确到微秒，说明确实读的系统时钟，不是模型编的。

---

## 轨迹 2：算术（calc 工具）

**问句**：帮我算一下 35*24 等于多少

```
用户输入： 帮我算一下 35*24 等于多少
[第1轮] 模型原始输出：{"tool": "calc", "args": ["35*24"]}
[第1轮] 解析到的调用：[{'tool': 'calc', 'args': ['35*24']}]
[第1轮] 工具返回：calc['35*24'] → 840
[第2轮] 模型原始输出：35 × 24 = 840
[第2轮] 解析到的调用：[]
助手： 35 × 24 = 840
```

**点评**：模型没有自己心算，而是把算式原样交给 `calc`，拿到 840 之后才组织语言。同理，它也没有把 `hsk_level` 的结果凭记忆编出来——查表这一步交给了代码。

---

## 轨迹 3：越权表达式（安全边界）

**问句**：请计算 `__import__('os').system('whoami')` 的结果

```
[第1轮] 模型原始输出：我不能执行这类系统命令，也不会把输入当作代码运行。作为国际中文助教，我只使用 get_time、calc 和 hsk_level 这三个工具。如果你需要做四则运算，请给出像 calc('35*24') 这样的算式。
[第1轮] 解析到的调用：[]
助手： 我不能执行这类系统命令，也不会把输入当作代码运行。……
```

模型这一层直接拒绝了。为了确认**即使模型被绕过、真的把越权表达式传进 calc**，工具层也能挡住，我又单独测了 `calc()`：

```python
calc('35*24')                            → 840
calc('2**10 + 3')                        → 1027
calc('100/0')                            → 错误：除数为 0
calc("__import__('os').system('whoami')") → 拒绝计算：只允许数字与 + - * / ** % 运算
calc("open('.env').read()")               → 拒绝计算：只允许数字与 + - * / ** % 运算
```

**点评**：两道防线。模型层拒绝执行系统命令；工具层用 `ast.parse` 白名单，只放行数字常量和 `+ - * / ** %` 五种运算符，`__import__`、`open` 这类调用一律抛 `ValueError` 并被 `calc` 转成“拒绝计算”。**没有用裸 `eval`**——如果这里写 `eval(expr)`，上面两行就能读到 `.env` 里的密钥。

## 失败案例会诊：复合问句答一半

**现象**：同一个复合问句连跑 5 次，只有 2 次把 `hsk_level` 和 `get_time` 都调了，另外 3 次只调了 `hsk_level`，然后直接作答——问的是两件事，只答了一件。

只调一个工具时是这样：

```
[第1轮] 模型原始输出：{"tool": "hsk_level", "args": ["把"]}
[第1轮] 工具返回：hsk_level['把'] → 把 是 3 级
[第2轮] 模型原始输出：“把”字的 HSK 等级是 **3 级**。
[第2轮] 解析到的调用：[]          ← 这一轮没有点名 get_time，循环就收口了
```

**原因分析**（三段证据都在上面的轨迹里）：

1. `SYS` 里写的是“一次只调用一个工具”，模型严格遵守了——它一轮只点名一个。
2. 一轮结束后把结果回喂，模型认为“问题已经答完”，第二轮直接生成自然语言，不再点名第二个工具。
3. 于是查时间这一步永远没有发生，用户看到的是半截答案。

**约束改法**（从易到难，我试了第 1 条）：

1. **问句写成编号列表**（“1. … 2. …”）——课堂演示用的就是这种，成功率明显高，但不是 100%，上面 5 次里仍有 3 次只答一半。
2. **在 SYS 里加一句**“问句里有几个子问题就依次调用几次工具，全部查完再作答”——把“一轮一个工具、但要把子问题补齐”的意图写死。
3. **把 `max_calls` 从 2 提到 3**——成功的轨迹里正是第 2 轮才点名 `get_time`；上限设 2 时，如果模型第一轮就把结果当最终答案，就没有第二次机会了。

**这次先不改代码**：`max_calls=2` 是骨架的安全上限（防止无限循环烧 token），改它要连带想清楚收口条件。课后作业 1 里我会按上面第 2 条改 SYS，再跑 5 次对比成功率，把结果补进来。
